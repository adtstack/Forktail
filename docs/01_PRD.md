# 01. Product Requirements Document

## 1. 제품 개요

### 문제

기존 고급 비교 도구는 유료이거나, Git 충돌 해결에 치우쳐 있거나, UI가 오래되었거나, 단순 텍스트 비교와 폴더 비교를 한 앱에서 자연스럽게 연결하지 못한다. 사용자는 코드 에디터를 열고 명령줄을 오가거나 유료 도구를 유지해야 한다.

### 해결책

로컬 텍스트 파일을 대상으로 한 빠르고 명확한 비교·병합 전용 데스크톱 앱을 제공한다. Phase 1에는 AI가 없다. 모든 자동 결과는 결정론적 알고리즘으로 재현 가능해야 한다.

### 대상 사용자

- 개발자: 브랜치·생성 코드·설정 파일을 비교한다.
- 서버/운영 관리자: 배포 전후 디렉터리와 설정을 비교한다.
- 문서/데이터 작업자: Markdown, JSON, YAML, CSV, 로그를 비교한다.
- 기존 Beyond Compare 사용자: 자주 쓰는 텍스트·폴더·3-way 기능만 무료로 원한다.

### 지원 입력 경계

- 편집기에서 열고 비교하거나 병합하는 내용은 텍스트 파일로 제한한다.
- 텍스트로 안전하게 판별되지 않는 파일은 내용을 디코딩하거나 미리 보지 않고 명확한 안내와 함께 거절한다.
- 폴더 비교는 일반 파일의 메타데이터·크기·해시를 기준으로 상태를 분류할 수 있다. 단, 해당 항목을 내용 비교 화면으로 여는 것은 텍스트 파일에만 허용한다.
- Phase 1에는 콘텐츠 유형별 전용 렌더러나 편집기를 두지 않는다.

## 2. 핵심 사용자 작업

### JTBD-1: 두 파일의 차이를 빠르게 찾기

사용자는 두 파일을 선택하고 변경 블록을 순서대로 탐색하며 문맥과 단어 단위 변경을 확인한다.

### JTBD-2: 두 폴더의 상태 파악

사용자는 두 루트를 선택하고 동일/변경/왼쪽만/오른쪽만/형식 충돌을 필터링한다. 양쪽에 존재하거나 한쪽에만 존재하는 일반 파일은 텍스트 판별을 거쳐 2-way 화면에서 연다. 한쪽에만 있는 파일은 반대쪽을 missing 가상 빈 문서로 표시한다.

### JTBD-3: 세 버전을 안전하게 병합

사용자는 Base/Ours/Theirs를 열고 자동 병합 결과를 확인한다. 충돌만 순회하며 원하는 내용을 선택하거나 직접 편집하고 저장한다.

## 3. Phase 1 기능 요구사항

### P0-A. 앱 셸과 세션

- 시작 화면에서 파일 비교, 폴더 비교, 3-way 병합을 선택한다.
- 취소한 파일 선택은 오류가 아니다.
- 현재 세션의 경로, 옵션, 편집 상태를 유지한다.
- 저장하지 않은 결과가 있을 때 화면을 떠나면 확인한다.
- 최근 세션은 로컬 설정에 최대 20개만 보관하며 파일 내용은 저장하지 않는다.

### P0-B. 2-way 텍스트 비교

- 파일 두 개를 선택한다.
- 줄 단위 및 단어 단위 차이를 나란히 또는 inline으로 표시한다.
- 다음/이전 변경으로 이동한다.
- 끝 공백 무시, 전체 공백 무시, 대소문자 무시 옵션을 제공한다.
- 줄바꿈 표시 및 word wrap을 전환한다.
- 좌우를 교환한다.
- 경로, 인코딩, 줄바꿈, 크기, 마지막 개행 여부를 표시한다.
- 바이너리 파일은 명확히 거절하고 텍스트로 표시하지 않는다.
- Phase 1.1에서 오른쪽 편집 및 hunk 복사를 제공한다.

수용 기준:

- 1,000줄 파일의 변경 50개를 키보드로 순회할 수 있다.
- 한쪽 파일이 빈 파일이어도 열린다.
- 마지막 개행 차이를 감지하고 표시한다.
- CRLF/LF 차이를 무시하거나 비교하는 옵션이 동작한다.

### P0-C. 폴더 비교

- 폴더 두 개를 선택한다.
- 재귀적으로 파일과 폴더를 수집한다.
- 상태를 `same`, `different`, `leftOnly`, `rightOnly`, `typeMismatch`, `error`로 분류한다.
- 비교 방식은 메타데이터, 빠른 해시, 전체 해시 세 가지다.
- 숨김 파일, `.gitignore`, 심볼릭 링크 추적 여부를 설정한다.
- 경로 텍스트 및 상태로 필터한다.
- 일반 파일 행의 단일 클릭은 선택만 바꾸고, 더블 클릭 또는 Enter를 누르면 텍스트 판별을 거쳐 2-way 비교로 연다. 한쪽에만 있는 파일은 반대쪽을 missing 가상 빈 문서로 표시한다. 텍스트가 아니면 상태만 유지하고 안내한다.
- 결과 목록은 폴더 우선 계층으로 묶는다. 상태·경로 필터에 맞는 파일의 상위 폴더는 문맥 행으로 유지하며, 접힌 폴더의 하위 항목은 표시하지 않는다.
- 긴 스캔은 진행률과 취소를 제공한다.
- 10,000개 이상 목록은 가상 스크롤한다.

수용 기준:

- 내용이 같고 timestamp만 다른 파일은 전체 해시 모드에서 `same`이다.
- 크기가 다른 파일은 해시를 읽지 않고 `different`다.
- 기본 설정에서 symlink를 따라가지 않는다.
- 권한 오류 하나가 전체 스캔을 중단하지 않고 해당 항목을 `error`로 표시한다.

### P0-D. 3-way merge

- Base, Ours, Theirs 파일을 선택한다.
- 결정론적 line-based 3-way merge를 실행한다.
- 비겹침 변경은 자동 결합한다.
- 겹침 변경은 diff3 형태의 Base 정보를 포함한 충돌로 표시한다.
- 충돌별로 Ours, Theirs, Base, Both를 선택한다.
- 결과는 직접 편집할 수 있다.
- 다음/이전 충돌 탐색과 남은 충돌 수를 제공한다.
- 충돌 마커가 0개일 때 완료 상태를 표시한다.
- Save As와 기존 경로 Save를 지원한다.

수용 기준:

- Ours가 첫 줄, Theirs가 마지막 줄을 수정한 입력은 깨끗하게 병합된다.
- 같은 줄을 다르게 수정하면 자동으로 한쪽을 고르지 않는다.
- 한 충돌 해결 후 나머지 충돌 offset이 정확히 재계산된다.
- 직접 마커를 편집해 제거해도 충돌 수가 갱신된다.

### P0-E. 안전한 파일 처리

- 텍스트 파일 크기 안전 한도를 둔다. 초기 기본값은 64 MiB다.
- BOM을 우선 사용하고, 없으면 인코딩을 탐지한다.
- 디코딩 손실 여부를 표시한다.
- 저장 시 같은 디렉터리에 임시 파일을 만든다.
- 내용을 flush하고 가능한 플랫폼에서 fsync 후 교체한다.
- 기존 파일 덮어쓰기 전 `.bak` 또는 버전 백업을 만든다.
- 저장 실패 시 기존 파일을 보존한다.
- 외부 변경 감지 후 덮어쓰기 전에 충돌 경고를 표시한다.

### P0-F. 키보드와 접근성

- 모든 주요 동작은 키보드로 가능하다.
- 색상만으로 상태를 표현하지 않는다.
- 폴더 행, 충돌, 변경 블록에 텍스트 레이블이 있다.
- 포커스 순서가 시각 순서와 일치한다.
- 확대 200%에서 핵심 기능이 잘리지 않는다.

## 4. 비기능 요구사항

아래 값은 보장된 성능이 아니라 릴리스 목표다.

- 일반 파일 비교 화면 표시: 선택 완료 후 1초 이내 목표
- 10,000 파일 메타데이터 스캔: 개발 기준 머신에서 5초 이내 목표
- UI 스레드 정지: 100ms 이상 작업은 Rust worker/async 경로로 이동
- 시작 메모리: Electron 대안보다 낮은 수준 유지
- 오프라인: 핵심 기능 100% 동작
- 개인정보: 기본 네트워크 요청 0건
- 회귀성: merge fixture는 동일 입력에 byte-identical 결과

## 5. 범위 밖

Phase 1에서 구현하지 않는다.

- AI 자동 해결·설명
- Hex/Binary 편집
- ZIP/7z 내부 비교
- FTP/SFTP/WebDAV/클라우드
- Git 클라이언트 전체 기능
- 데이터베이스 스키마 비교
- 플러그인 마켓
- 협업·계정·동기화

`MRG-009`의 외부 `git mergetool` 경로 adapter는 기존 3-way 화면을 여는 제한된 CLI 통합이다. branch/commit/index를 탐색하는 repository-aware Git 기능은 Phase 1에 포함하지 않으며, 안정화 이후 후보인 `docs/17_GIT_INTEGRATION.md`에서 별도로 다룬다.

## 6. 출시 기준

`docs/12_DEFINITION_OF_DONE.md`의 모든 Release DoD를 만족해야 한다. 특히 저장 내구성, 인코딩 회귀, 세 운영체제 smoke test가 끝나기 전에는 stable 태그를 만들지 않는다.
