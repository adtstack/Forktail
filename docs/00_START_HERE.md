# 00. 시작점

## 한 문장 정의

forktail은 **두 파일·두 폴더·세 버전의 텍스트를 로컬에서 안전하게 비교하고 병합하는 무료 데스크톱 도구**다.

## 왜 이 범위인가

Beyond Compare 전체를 처음부터 복제하면 바이너리 편집, 아카이브, 원격 파일 시스템, 규칙 엔진, 리포트 등 주변 기능에 묻혀 핵심 경험이 늦어진다. 첫 릴리스는 반복 사용 빈도가 높은 세 흐름만 완성한다.

1. 파일 2-way 비교
2. 폴더 비교 후 변경 파일 열기
3. 3-way 자동 병합 후 충돌 해결

Phase 1의 편집기 비교·병합 대상은 텍스트 파일로 제한한다. 폴더 비교는 모든 일반 파일을 메타데이터나 해시로 분류할 수 있지만, 텍스트로 안전하게 판별되지 않는 항목은 내용 비교 화면으로 열지 않는다. AI 기능은 기본 병합의 정확도와 테스트 기반이 안정된 뒤 독립 모듈로 추가한다.

## 제품 원칙

- **Local-first**: 네트워크 연결이 없어도 모든 핵심 기능이 동작한다.
- **No surprise writes**: 비교만 하다가 파일이 바뀌는 일은 없어야 한다.
- **Review before apply**: 병합 결과는 사용자가 보고 저장한다.
- **Fast path first**: 키보드만으로 다음 차이·채택·저장이 가능해야 한다.
- **Text fidelity**: 인코딩, 줄바꿈, 마지막 개행을 가능한 한 보존한다.
- **Scope discipline**: Phase 1은 기본기 외 기능을 거절한다.

## 사용자가 얻게 될 최소 경험

```text
앱 실행
  → 파일 2개 선택
  → 변경 블록 탐색
  → 필요한 쪽을 결과에 반영
  → 백업과 함께 저장
```

또는:

```text
폴더 2개 선택
  → 변경/한쪽 전용 파일 필터
  → 파일 항목 클릭
  → 파일 비교
```

또는:

```text
BASE / OURS / THEIRS 선택
  → 자동 병합
  → 충돌만 순회하며 OURS/THEIRS/BASE/BOTH 선택
  → 충돌 0개 확인
  → 저장
```

## 성공 판단

Phase 1은 다음 조건을 모두 만족할 때 끝난다.

- 일상적인 UTF-8/UTF-16 텍스트 파일을 손실 없이 열고 저장한다.
- 서로 다른 줄을 수정한 3-way 입력은 자동 병합한다.
- 겹친 수정은 명시적 충돌로 남기며 한 번의 클릭/단축키로 해결할 수 있다.
- 폴더 비교 결과가 선택한 비교 방식과 일치한다.
- 앱 충돌 또는 저장 실패가 기존 파일을 손상시키지 않는다.
- Windows, macOS, Linux 각각에서 smoke test를 통과한다.
- 네트워크 호출과 AI 의존성이 없다.

## 바로 실행할 순서

1. 저장소를 Git에 올린다.
2. `FND-001`부터 GitHub Issue로 만든다.
3. AI 에이전트에게 `docs/06_PROMPT_PACK.md`의 구현 프롬프트와 이슈 하나만 준다.
4. 작은 PR로 병합한다.
5. 매 milestone 종료 시 fixture 전체 회귀 테스트를 실행한다.
