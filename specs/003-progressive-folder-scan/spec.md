# Feature Specification: Progressive Folder Scan

**Feature Branch**: Not created — specification added on `main`

**Issue**: `FOL-006R`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "대용량 폴더 비교에서 전체 결과를 기다리지 않고 파일과 폴더를 빠르게 먼저 보여주며, 진행 중에도 안전하게 검토할 수 있게 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 도착한 결과부터 검토하기 (Priority: P1)

사용자는 수만 개 파일이 있는 두 폴더의 비교를 시작한 뒤 전체 작업이 끝날 때까지 빈 화면을
기다리지 않는다. 확인된 폴더와 파일이 폴더 계층 안에 계속 나타나고, 이미 확정된 항목부터 선택해
검토할 수 있다.

**Why this priority**: 현재 체감 지연의 가장 큰 원인은 전체 결과가 완성될 때까지 아무것도 볼 수
없다는 점이다. 첫 결과를 빨리 보여주면 총 완료 시간이 같더라도 사용자는 즉시 검토를 시작할 수 있다.

**Independent Test**: 생성한 10,000개 항목 폴더를 비교해 완료 전에 첫 폴더·파일 항목이 보이고,
확정된 일반 텍스트 파일을 선택해 읽기 전용 비교를 열 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 10,000개 이상의 항목이 있는 유효한 두 폴더, **When** 사용자가 비교를 시작하면, **Then** 전체 비교가 끝나기 전에 발견된 폴더와 파일이 폴더 계층 안에 점진적으로 표시된다.
2. **Given** 일부 항목이 표시되었지만 비교가 진행 중인 상태, **When** 사용자가 확정된 일반 텍스트 파일을 선택하고 열면, **Then** 진행 중인 폴더 비교를 중단하지 않고 해당 파일 쌍을 읽기 전용으로 검토할 수 있다.
3. **Given** 아직 내용 확인이 필요한 같은 크기의 파일 쌍, **When** 해당 경로가 먼저 발견되면, **Then** 앱은 이를 `같음` 또는 `다름`으로 성급히 단정하지 않고 확인 중임을 명확히 표시한다.
4. **Given** 한쪽에만 있거나 종류·크기가 명백히 다른 항목, **When** 필요한 정보가 확인되면, **Then** 해당 상태는 다른 항목의 내용 확인이 끝날 때까지 기다리지 않고 확정되어 표시된다.

---

### User Story 2 - 진행 상태와 최종 결과 신뢰하기 (Priority: P2)

사용자는 현재 무엇을 하고 있는지, 얼마나 발견했고 얼마나 판정했는지, 비교가 끝났는지 알 수 있다.
진행 중 수치와 최종 수치가 구분되며 완료 후 결과는 기존의 동일한 비교 옵션으로 얻은 정확한 결과와
일치한다.

**Why this priority**: 점진 표시가 잘못된 확정 상태나 흔들리는 총계로 보이면 속도 향상이 오히려
신뢰를 낮춘다. 진행 중인 판정과 최종 판정을 구분해야 예측 가능한 검토가 가능하다.

**Independent Test**: 같은 fixture를 점진 비교와 완전 비교로 각각 실행해 최종 경로·상태·오류·통계가
모두 일치하고, 진행 중에는 발견·판정·내용 확인 단계와 임시 수치가 구분되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 대용량 폴더 비교가 진행 중인 상태, **When** 사용자가 상태 영역을 보면, **Then** 발견한 항목 수, 판정이 끝난 항목 수, 추가 확인 중인 항목 수와 현재 단계를 구분할 수 있다.
2. **Given** 진행 중인 항목의 판정이 나중에 확정된 상태, **When** 화면이 갱신되면, **Then** 같은 경로의 한 항목이 제자리에서 확정 상태로 바뀌고 중복 행이 생기지 않는다.
3. **Given** 비교가 정상 완료된 상태, **When** 최종 통계를 확인하면, **Then** 모든 표시 항목은 확정 상태이고 상태별 합계는 실제 최종 항목 수와 일치한다.
4. **Given** 개별 경로에서 권한 또는 읽기 오류가 발생한 상태, **When** 나머지 경로가 유효하면, **Then** 오류 경로만 행동 가능한 오류로 표시되고 다른 항목의 발견과 판정은 계속된다.

### User Story 3 - 취소하고 새 비교로 안전하게 전환하기 (Priority: P2)

사용자는 오래 걸리는 비교를 취소하거나 루트·옵션을 바꾸어 새 비교를 시작한다. 이전 작업에서 늦게
도착한 결과는 새 화면에 섞이지 않으며, 취소가 확인된 뒤 이전 작업 때문에 목록이 다시 늘어나지 않는다.

**Why this priority**: 빠른 결과 표시를 위해 중간 결과가 여러 번 도착하면 오래된 작업의 결과가 현재
화면을 오염할 위험이 커진다. 데이터 안전성과 예측 가능성을 위해 반드시 함께 닫아야 하는 조건이다.

**Independent Test**: 지연을 넣은 100,000개 항목 비교 도중 취소, 옵션 변경, 새 루트 비교를 연속으로
실행해 현재 비교 identity와 다른 항목이 한 건도 화면에 반영되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비교가 진행 중인 상태, **When** 사용자가 취소하면, **Then** 1초 안에 취소가 확인되고 이후 이전 작업의 항목이 현재 결과에 추가되지 않는다.
2. **Given** 첫 비교가 아직 결과를 보내는 중인 상태, **When** 사용자가 다른 루트 또는 옵션으로 새 비교를 시작하면, **Then** 화면은 새 비교 결과만 받아들이고 이전 비교의 늦은 결과를 모두 무시한다.
3. **Given** 비교 화면이 닫히거나 다른 모드로 전환된 상태, **When** 이전 작업의 결과가 늦게 도착하면, **Then** 닫힌 화면의 상태를 갱신하거나 사용자에게 잘못된 완료 알림을 표시하지 않는다.
4. **Given** 비교가 실패하거나 취소된 상태, **When** 사용자가 같은 폴더를 다시 실행하면, **Then** 이전 실행의 임시 상태나 오류가 남지 않은 새 결과 집합에서 시작한다.

### Edge Cases

- 한쪽 폴더가 비었거나 스캔 중 비워지는 경우에도 발견된 한쪽 항목은 올바른 단독 상태로 남는다.
- 스캔 도중 파일이 생성·삭제·이동·수정되면 해당 항목은 서로 다른 시점의 정보를 조합해 확정하지
  않고 외부 변경 또는 읽기 오류로 격리한다.
- 파일과 폴더가 같은 상대 경로에 있는 경우 종류 불일치가 확정되며 자식 항목은 잘못된 부모 아래로
  합쳐지지 않는다.
- 대소문자나 Unicode 정규화 규칙 때문에 같은 표시 경로가 충돌하면 한 항목으로 조용히 덮어쓰지
  않고 경로 충돌로 표시한다.
- 권한 없는 하위 폴더, 끊어진 링크, 순환 링크, 특수 파일은 다른 정상 경로의 진행을 막지 않는다.
- 심볼릭 링크는 기본으로 따라가지 않으며 옵션으로 허용된 경우에도 루트 이탈과 순환을 안전하게
  처리한다.
- 숨김 파일과 ignore 규칙은 시작 시 선택한 옵션을 전체 실행에 일관되게 적용한다.
- 필터를 켜고 끄거나 폴더를 접고 펴도 현재까지 받은 항목과 최종 통계가 유실되거나 중복되지 않는다.
- 매우 빠른 생산 속도나 느린 화면 갱신에서도 메모리가 항목 수와 무관하게 순간적으로 무제한 증가하지
  않고, 화면 입력이 장시간 멈추지 않는다.
- 항목 수를 미리 알 수 없는 동안 백분율을 거짓으로 추정하지 않고, 알 수 있는 단위의 진행 수치를
  표시한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 폴더 비교가 완료되기 전에 발견되고 판정 가능한 폴더·파일 항목을 폴더 계층 안에 점진적으로 표시해야 한다.
- **FR-002**: 시스템은 각 표시 항목이 추가 확인 중인지 최종 판정되었는지 구분해야 하며, 최종 근거가 없는 항목을 `같음` 또는 `다름`으로 표시해서는 안 된다.
- **FR-003**: 시스템은 현재 비교 옵션에서 메타데이터만으로 확정할 수 있는 단독 항목, 종류 불일치, 크기 불일치를 추가 내용 확인이 필요한 항목과 독립적으로 확정해야 한다.
- **FR-004**: 시스템은 같은 상대 경로의 중간 정보와 최종 판정을 하나의 안정된 항목으로 갱신하고 중복 행을 만들지 않아야 한다.
- **FR-005**: 시스템은 폴더가 파일보다 먼저 이해되도록 계층 구조를 유지하고, 실제 폴더 항목이 늦게 도착하더라도 이미 표시한 자식의 경로 문맥을 잃지 않아야 한다.
- **FR-006**: 사용자는 비교 중에도 폴더 접기·펼치기, 필터 변경, 표시된 항목 선택, 확정된 일반 텍스트 파일 열기를 수행할 수 있어야 한다.
- **FR-007**: 시스템은 진행 중 발견 항목 수, 최종 판정 항목 수, 추가 확인 중 항목 수, 오류 수와 현재 작업 단계를 접근 가능한 상태로 표시해야 한다.
- **FR-008**: 총 작업량을 아직 알 수 없을 때 시스템은 근거 없는 완료 백분율을 표시하지 않아야 하며, 완료 시점에는 정확한 최종 통계와 소요 시간을 표시해야 한다.
- **FR-009**: 정상 완료된 결과의 경로, 상태, 오류 및 통계는 같은 루트와 옵션을 사용한 기존 완전 비교 결과와 동일해야 한다.
- **FR-010**: 모든 중간 결과는 실행 identity와 순서를 가져야 하며, 시스템은 현재 루트·옵션·실행과 일치하지 않거나 이미 반영한 결과를 무시해야 한다.
- **FR-011**: 사용자는 진행 중인 비교를 취소할 수 있어야 하며 취소 확인 후 해당 실행의 항목이 현재 결과에 추가되어서는 안 된다.
- **FR-012**: 루트 또는 비교 옵션을 바꾸어 새 비교를 시작하면 시스템은 이전 실행을 현재 결과로부터 즉시 분리하고 새 실행의 결과만 표시해야 한다.
- **FR-013**: 개별 경로의 권한, 메타데이터, 내용 확인 오류는 해당 경로에 격리하고 나머지 비교를 계속해야 한다.
- **FR-014**: 시스템은 화면이 처리할 수 있는 속도를 넘는 중간 결과가 발생해도 대기 중 데이터가 무제한 증가하지 않도록 제한해야 한다.
- **FR-015**: 시스템은 진행 중 동일 경로의 외부 변경을 감지하면 서로 다른 시점의 정보를 조합해 최종 판정하지 않고 해당 항목을 명시적 오류 또는 외부 변경 상태로 처리해야 한다.
- **FR-016**: 시스템은 10,000개 및 100,000개 생성 fixture에서 첫 결과 도착, 최종 정확성, 취소 반응, 메모리 상한을 반복 측정할 수 있어야 한다.

### Safety, Privacy, and Scope Requirements *(mandatory)*

- **SR-001**: 이 기능은 사용자 파일, 폴더, 권한, 이름, 타임스탬프 또는 내용을 변경하지 않는 읽기 전용 비교이며, 앱 설정과 최근 세션에도 새로운 내용을 저장하지 않아야 한다.
- **SR-002**: 파일 내용, 해시 입력, 상대·절대 경로, 중간 결과를 network, telemetry, 오류 보고 또는 일반 로그로 보내지 않아야 한다. 진단 로그는 내용과 경로가 없는 실행 identity, 단계, 개수, 시간, 오류 code만 포함할 수 있다.
- **SR-003**: binary 파일을 텍스트로 디코딩하지 않고, 심볼릭 링크를 기본으로 따라가지 않으며, 모든 파일 열기는 기존의 루트 포함 관계·파일 종류·크기·외부 변경 검증을 유지해야 한다. 취소 및 stale-result 무시는 모든 장시간 단계에 적용해야 한다.
- **SR-004**: 폴더 동기화 적용, 자동 쓰기, 원격·네트워크 폴더 특화 최적화, 파일 시스템 감시를 통한 live 지속 동기화, 디스크 기반 scan cache, 검색 색인, 압축 파일 내부 비교는 이 기능의 범위 밖이다.

### Key Entities *(include if feature involves data)*

- **Scan Identity**: 한 번의 폴더 비교 실행을 루트, 옵션, generation과 함께 유일하게 구분하며 이전 실행 결과를 배제하는 수명 한정 identity다.
- **Progressive Entry**: 상대 경로, 양쪽의 확인된 존재·종류·메타데이터, 현재 판정 단계, 최종 상태 또는 경로별 오류를 가진 점진 갱신 항목이다.
- **Scan Progress**: 발견·판정·추가 확인·오류·완료 수치와 현재 단계를 나타내며 총량을 모를 때는 거짓 백분율을 만들지 않는다.
- **Scan Summary**: 정상 완료, 취소 또는 실패라는 종료 상태와 최종 통계, 소요 시간, 실행 identity를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 기준 개발 장비의 생성된 10,000개 metadata fixture에서 비교 시작 후 500ms 안에 첫 200개 항목 또는 전체 결과 중 먼저 충족되는 쪽이 화면에 표시된다.
- **SC-002**: 생성된 10,000개 및 100,000개 fixture에서 첫 항목은 전체 비교가 끝나기 전에 표시되고, 표시 항목 수가 완료 시점까지 중복 없이 증가하거나 제자리에서 확정 상태로 갱신된다.
- **SC-003**: 같은 fixture를 기존 완전 비교와 점진 비교로 각각 실행했을 때 최종 상대 경로, 양쪽 메타데이터, 상태, 오류 및 상태별 합계가 100% 일치한다.
- **SC-004**: 100,000개 fixture 비교 중에도 단일 사용자 입력이 100ms 넘게 막히는 사례가 없고, 비교 때문에 추가되는 peak memory는 기준 실행 시작점 대비 250MiB 이하로 유지된다.
- **SC-005**: 진행 중 취소는 요청 후 1초 안에 확인되며, 취소·새 실행·화면 종료를 각각 100회 반복한 시험에서 stale 항목 반영과 취소 후 항목 추가가 모두 0건이다.
- **SC-006**: 권한 오류 1건, 내용 확인 오류 1건, 외부 변경 1건을 포함한 fixture에서 정상 항목의 최종 결과 누락은 0건이고 세 오류는 각각 해당 경로에 격리된다.
- **SC-007**: keyboard-only 사용자는 진행 중인 목록에서 폴더 접기·펼치기, 필터, 확정 파일 선택·열기, 취소를 모두 완료할 수 있고 진행 및 종료 상태를 보조 기술로 확인할 수 있다.

## Assumptions

- 첫 성능 목표는 로컬 SSD의 일반 디렉터리이며 네트워크 드라이브 성능 보장은 별도 범위로 둔다.
- `metadata`, `quick hash`, `full hash` 비교 옵션의 의미와 최종 판정 기준은 바꾸지 않는다.
- 명백한 단독·종류·크기 불일치는 일찍 확정할 수 있지만, 선택한 비교 옵션이 요구하는 내용 확인을 마치기 전에는 같은 크기 파일의 동일 여부를 확정하지 않는다.
- 사용자가 진행 중 확정된 일반 텍스트 파일을 여는 것은 허용하되 폴더 스캔 자체는 계속된다.
- 성능 fixture와 기준 장비 사양은 benchmark 결과와 함께 기록해 회귀 비교가 가능하게 한다.

## Dependencies and Out of Scope *(mandatory)*

- **Dependencies**: `FOL-006R`, 기존 `FOL-002` scan options와 상태 계약, `FOL-007` virtual scroll, 현재 folder tree identity/filter contract, cancellable folder review pair reader, binary/symlink/path-containment 정책.
- **Out of scope**: 최종 비교 의미 변경, 폴더 동기화 적용, 자동 파일 수정, persistent scan cache, file watcher 기반 연속 비교, 원격 스토리지 최적화, 아카이브 내부 비교, 새 compare mode 추가.
